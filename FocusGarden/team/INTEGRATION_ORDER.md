# 持续整合顺序

A日1先发布可编译公共基线，七页与服务对象只创建一次，声明和Mock端口齐备。B当天优先交真实Repository/schema和C需要的原子事务端口；D优先交SettingsService给B；C依据冻结端口实现奖励和喂食。四人在同一基线同步开发完整功能，不是等A做完全部页面才开始。

日2优先合并任务持久化、真实设置、基础播放与C服务；日3闭合真实计时→保存→C结算→A刷新；日4补齐统计、全部弹窗和所有PRD异常；日5从Live空库执行全功能、重启、真实音频和自然完成验收。能编译的独立改动尽早小PR合并；不得第5天才第一次整合。

第6天以后只做全链路测试、缺陷修复、视觉/性能稳定性优化、Windows部署、实验报告和答辩材料。某必做项日5缺失就如实标未完成，不改成演示通过，也不把它包装为计划中的后续功能开发。
