# 队长第1天操作手册

今天的结果应该是：四人电脑确定同一Kit；你拿到一个真正能配置、编译、打开且能切七页的公共工程；它已上传同一个GitHub，B/C/D能克隆并在原文件继续做完整业务。日1公共壳可用占位，整个项目的第5天目标仍是全部真实功能。

## 1 先确认环境 这一步不要猜

把下面这段发到你们自己的组内群（本资料不会代发）：

请每人打开Qt Creator的Preferences/首选项或Tools/Options中的Kits，回报：Windows版本与64位、Qt完整6.x.y、编译器家族及完整版本、Kit完整名称、CMake版本、是否有Widgets/Svg/Multimedia/Sql/Test。请把这些值填到仓库ENVIRONMENT_LOCK对应列。不要只回答“装了Qt Creator”。

Kit可以理解为“Qt库＋编译器＋调试/构建工具的一整套搭配”。Qt Creator只是编辑器，安装它不代表Qt库和编译器已齐。四人用同一Qt补丁版本和同一编译器家族/架构；MinGW与MSVC不混用。若四人已有相同能构建的Kit，就锁它；否则由你选安装器里四人都能装到的一套，再统一填写，别照文档示例凭空写已安装。

本蓝图最低Qt6.4，CMake3.21，C++17；实际锁定值以四台机器核实为准。目录可用C:/Projects/FocusGarden，Qt安装路径各机可不同，别写进共享CMake。GitHub地址/初始基线SHA由你建立后填，不是本次整理者能代猜。

## 2 准备唯一仓库文件夹

若已有共享仓库，Desktop克隆它。将工程资料版中的00～08目录与FocusGarden目录放在仓库根，保留名称。不要上传“本地归档”。此刻尚无Qt_UI_Starter，等下一次Codex创建；不要自己手动建四份工程。

## 3 给Codex什么

最好让Codex打开整个仓库根目录。它会按“第1天完整Codex指令.md”的精确清单读取文件。若只能上传压缩包，上传工程资料版并要求先解压到同一工作区；队长阅读版不含共享资源，不能用它生成工程。不要只上传PRD或只上传某一页截图。

## 4 复制完整指令

打开本目录《第1天完整Codex指令.md》，整段复制给Codex。下面文档附录也收录同样内容。告诉它先做公共基线，成功后交日志和文件，不只解释步骤。该次日1操作不替B/C/D写完整业务；你之后仍按A完整任务书整合全部真实功能到第5天。

## 5 应先出现哪些目录与文件

| 目录或文件 | 为什么必须先有 | 谁接着编辑 |
|---|---|---|
| Qt_UI_Starter/CMakeLists.txt | 所有人从同一入口构建 | A维护 |
| src/contracts/DomainTypes.h、ServicePorts.h | 不让AI各发明Task/Result/接口 | A维护声明，全员读取 |
| src/main.cpp、AppComposition、MainWindow | 唯一对象装配、主窗口和导航 | A |
| src/services/AppServices、CompletionCoordinator | 转发与B保存后调C，不互相依赖 | A |
| src/pages七个页面类 | 各人接入原位置，不另画主窗口 | 各页负责人 |

| src/ui公共组件与共用框 | 同一视觉，不各复制QSS | A，任务表单业务B |

这些是下一次Codex必须创建的目标，不是本次包里已存在的Qt源文件。日1输出若缺公共头/槽/占位、别人无法配置，就还没完成基础工程。

## 6 检查唯一主窗口和导航

运行后只出现一个MainWindow。左侧七项都能切到对应标题；重复切页不弹第二个窗口。让Codex说明每个页面在哪里创建，只能创建一次；服务放AppComposition，不放页面构造里。SettingsPage与SettingsService占位后交D，A只接入与整合。

## 7 检查QSS QRC和真实素材

CMake直接引用仓库FocusGarden/resources.qrc，不把main.qss、UI_ASSETS搬进四个模块。QRC中图片相对位置不改，运行读取:/fg/main.qss和:/fg/UI_ASSETS/...。让Codex实际检查Logo、七图标、三等级PNG及状态图能加载；Qt资源不靠浏览器Emoji充数。

## 8 检查模型 服务和占位

让Codex逐项对照FG-API：所有公共结构只在contracts里；AppServices仅一份转发；Coordinator仅一份；B的Repo声明包含C两个原子方法；D的设置端口包含preferences/savePreferences和音乐内部路径配置。占位清楚标演示，未实现不返回假成功。

真实业务并行顺序：B优先仓库及原子端口，D优先设置给B，C实现奖励和宠物规则，A负责接线。Mock不算软件功能完成，第5天必须全部替换为真实业务装配。

## 9 在Qt Creator验证真的能运行

选择File → Open File or Project，打开Qt_UI_Starter/CMakeLists.txt；选择ENVIRONMENT_LOCK里同一Desktop Kit，点Configure。配置失败复制完整错误给Codex，不反复随意切换另一编译器。

点击Build/构建，完成后点Run/绿色三角。保存Compile Output日志和窗口截图。依次点七页，检查Logo/图标和窗口缩放；再关闭重开。若只看到Codex说“写完了”、没有自己电脑窗口和日志，不能宣布日1工程通过。

可交给Codex执行的等价命令（真实Qt路径由本机Kit给出，不把尖括号示例当现成路径）：

```sh
cmake -S Qt_UI_Starter -B build -DCMAKE_PREFIX_PATH=<本机对应Qt Kit路径> -DBUILD_TESTING=ON
cmake --build build --config Debug
ctest --test-dir build -C Debug --output-on-failure
```

日1这些只证明基础壳，不能证明数据库/奖励/音频已实现。第5天另跑全功能Live验收。项目包当前没有上述可构建工程，本次没有执行这些命令。

## 10 上传GitHub并移交

检查忽略清单：不传build、Qt Creator个人.user、真实数据库/app.ini、歌曲或凭据。提交中文资料、唯一FocusGarden、Qt_UI_Starter源码与测试说明。Desktop Commit后Push；写下基线SHA。把“仓库地址＋基线SHA＋四人各自中文目录”发组内，不每天重新发任务。

B/C/D克隆同一仓库，main Fetch/Pull后先构建原基线，确认无误再New Branch。缺公共文件由A修公共壳，不各自另建工程。第1天就开Draft PR，日2起持续合并可编译小功能，第5天前闭合全部真实业务。

## 11 日1交接勾选

环境4人一致；公共声明一份；七页可切；服务/页面仅创建一次；qrc素材可加载；成员具体类与测试接入点存在；构建/运行日志真实；基线已Push并有SHA；角色任务书和输入清单都能找到。任何一项缺失就写阻塞项，不伪称已准备完毕。
